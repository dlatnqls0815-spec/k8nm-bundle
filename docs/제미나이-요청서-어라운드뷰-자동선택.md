# 요청: 네메시스 서비스로 "주행 중 카메라 버튼 → 어라운드뷰 자동 선택" 만들기

## 만들 것
- 네메시스 패키지 하나: 백그라운드 서비스(`mode=restart`, `uid=system`).
- 앱 안에 코드를 넣지 않는다(서개모 hook_apps 안 씀). 그래서 설치·업데이트·설정 변경에 재부팅이 필요 없어야 한다.
- 화면 자르기, 오른쪽 칸, 분할화면, 테마 연동은 전부 없음. 순정 전체 화면 그대로.
- 켜고 끄기는 앱 주입이 없는 서개모 카드 하나(`restart=none`)에서 `persist.sys.k8avs.on` 같은 값으로 넘긴다. 서비스는 이 값을 그때그때 읽는다.

## 동작
1. 서비스가 카메라 상태(보기 번호)를 계속 받는다.
2. 카메라가 꺼짐(1)에서 켜진 직후 한 번만:
   - 21이면 `requestSelectMenu(10)`("후방카메라") → 23이 되면 `requestSelectMenu(15)`("어라운드뷰") → 22면 끝.
   - 23이면 `requestSelectMenu(15)`만 → 22면 끝.
   - 2, 3, 22이면 아무것도 안 함.
3. 6초 안에 안 끝나거나, 후진·화면 꺼짐·예상 밖 보기면 그 세션은 포기. 재시도 없음.
4. 사람이 버튼을 직접 눌러 다른 보기로 바꾸면 그대로 둔다.

## 차에서 확인된 값 (K8 GL3, 2026-11-19)
- 보기 번호: 1 꺼짐, 2 P단 후방+탑뷰, 3 D단 정차 전방+탑뷰, 21 주행 중 버튼 직후, 23 주행 후방 와이드, 22 주행 후방+어라운드뷰.
- 실제 기록: `view 1 -> 23`, `requestSelectMenu(15) -> 1`, `view 23 -> 22`. 21에서는 10을 먼저 보냈을 때 23으로 갔음.
- 클래스(`/system/framework/automotive.jar`):
  - `com.hkmc.pgs.AvmManager`: 생성자 `AvmManager(Context)`, `addListener(AvmStatusListener)`, `requestSelectMenu(int)`
  - `com.hkmc.pgs.AvmStatusListener`: `onAvmStatus(int viewMode, int display, int rearOpt, int frontOpt)` 등
- 지금까지는 카메라 앱 안에서 이 클래스를 썼다(동작 확인). 서비스 프로세스에서 쓰는 건 아직 시험 전.

## 구현 힌트
- 실행 방식은 기존 패키지 `research/k8-auto-heat/nemesis/svc/heat.sh`를 따른다: `ANDROID_DATA=<개인 폴더> CLASSPATH=<dex>:/system/framework/automotive.jar exec app_process /system/bin <메인클래스>`.
- 메인에서 `Looper.prepareMainLooper()` → Context 얻기 → `new AvmManager(ctx)` → `addListener` → `Looper.loop()`.
  - Context 후보: `android.app.ActivityThread.systemMain().getSystemContext()`. 안 되면 AvmManager 내부가 쓰는 시스템 서비스를 직접 바인더로 부르는 방법을 찾는다(자동차 모듈 DEX를 `dexdump`로 확인).
- API 19(안드로이드 4.4), JDK 8 문법, d8로 DEX.
- 첫 단계는 "읽기만": 리스너 등록과 보기 번호 기록만 하는 버전을 만들어 차에서 확인한 뒤, 버튼 누르기를 켠다.

## 꼭 지킬 것
- 사용자 승인 전에는 차에 설치·전송하지 않는다.
- 차량 요청은 `requestSelectMenu(10)`, `requestSelectMenu(15)`만. 다른 CAN·바이너 송신 금지.
- `persist.service.adb.tcp.enable=1` 다시 켜지 않는다. HMG-API와 서개모를 섞지 않는다.
- 지금 차에 켜진 서개모 `ccnc-svm-5w`(같은 자동 선택 포함)는 새 기능을 켜기 전에 서개모 앱에서 끄고 재시작한다. adb에서 끄면 `/system/bin/app_process` 소유자가 깨진다.
- 로그·APK·차량 식별정보는 저장소에 올리지 않는다.
